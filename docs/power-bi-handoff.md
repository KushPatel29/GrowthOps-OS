# Power BI and Excel

Both are built from the same governed snapshot: `python -m growthops.export_bi` writes one CSV per verified
dbt mart to `dashboards/powerbi-data`, plus four BI shapes a mart does not carry: a daily `dim_date`, a
`dim_campaign`, lead-creation cash attribution at payment grain (`fact_cash_attribution`, which sums to net
cash to the cent) and a `quality_scorecard`. A number in the report, a cell in the workbook and a figure in
the Streamlit app are one definition read three ways, and the tests hold them equal.

```powershell
python -m growthops.verify_dbt                     # dbt marts == Python reference
python -m growthops.export_bi --refresh-pbip       # CSV snapshot + regenerate the whole PBIP project
python -m growthops.export_excel --recalculate     # rebuild the workbook, calculate it in Excel (Windows)
python -m growthops.bi.build_pbip --check          # CI: the committed project matches the spec and data
```

## Power BI report

Open [`GrowthOpsOS.pbip`](../dashboards/powerbi-project/GrowthOpsOS.pbip) in Power BI Desktop. The data is
embedded in each import partition as an M `#table` literal, so the project opens with no data path, gateway
or credentials; after opening, **Home → Refresh** loads it (a `.pbip` stores the definition, not the data).

Nothing in the project is hand-edited. It is generated by [`growthops/bi`](../growthops/bi):
`model_spec.py` (21 tables, 8 relationships, 215 described measures in display folders), `report_spec.py`
(7 pages, 121 visuals) and `report_chrome.py` (the frame every page shares), written out by `build_pbip.py`.
CI regenerates it and fails on any difference, so the report cannot drift from its spec or its data.

| Page | Question it answers |
|---|---|
| Executive summary | How are the last 28 days going against the 28 before? KPI tiles, a written summary computed from the measures, net cash and spend by month, paid MQL rate by platform, cash ROAS by campaign |
| Revenue truth | How do platform claims, explicitly qualified pipeline, CRM bookings and net cash differ? The CRM-to-cash bridge as a waterfall of the gap, platform claims against warehouse cash, ROAS as reported and on net cash |
| Paid media efficiency | What does paid media cost at each step? CPL by month and platform, cost per booked call by campaign, a campaign scorecard |
| Funnel and lead quality | Where do people stop, and which campaigns bring leads that do not qualify? The lifecycle funnel, paid MQL rate by channel and by campaign, the CTA test decided on cash per visitor |
| Attribution and content | Where did cash come from? Net cash by month and creating channel, by campaign, content to cash |
| Email and deliverability | Is email still reaching people? Bounce rate by week and sending domain, human against reported opens, a table by type and domain |
| Tracking, data quality and operations | Can we trust the data? UTM and migration checks against target, the short-link registry, the incident register, the renewal queue |

**What makes it usable.** Each KPI is an SVG tile drawn by a measure: the figure, a caption and, where the
figure has a direction, a green or red arrow for whether the move was good (a cost going up is red). Tiles on
the analysis pages compare the dates in view with the same number of days before them; the executive tiles
are fixed to the 28 days ending on the as-of date. Every page has a header that names the filters in effect,
Previous/Next buttons and a **Filters** button that opens a slicer panel (two bookmarks); buttons take
Ctrl+click in Desktop and a plain click in the Service. Conditional colours mark the campaigns returning under
1.0x and the checks under target. Every visual carries alt text.

**Checked, not assumed.** Before publishing, the project was parsed by Desktop's own TMDL serializer, the
report passed Microsoft's `powerbi-report-author validate` with zero errors and warnings, and the model was
opened in Power BI Desktop 2.157, refreshed, and queried: every table's row count equals its CSV, every one of
the 262 measures (215 described, 47 for the report's own tiles and headers) evaluates without an error, and
each page was screenshotted and reviewed (see `docs/images/pbi-*.png`). The v2.1 project was checked this way
again on 2026-09-30, after the Revenue truth page gained its qualified-pipeline tile.
`tests/test_powerbi.py` pins the failure modes Power BI does not report: unbound fields, untyped columns,
tables missing from `PBI_QueryOrder`, numeric literals without a type suffix, reserved VAR names, keys missing
from a dimension (a "(Blank)" member on every axis), overlapping visuals and SVG encoding.

The measure reference is generated: [power-bi-measures.md](power-bi-measures.md).

## Excel workbook

[`GrowthOps_OS_Excel_Dashboard.xlsx`](../dashboards/GrowthOps_OS_Excel_Dashboard.xlsx): one input, the
reporting window on the Dashboard (Last 7, 28 or 90 days, month or quarter to date, or custom dates), drives
every windowed figure through named ranges; `Calc` shows how each date is derived.

| Sheet | Contents |
|---|---|
| Cover | Data-through date, the window, the audit result, and a linked guide to every sheet |
| Dashboard | Six KPI tiles against the prior window with coloured deltas, three sentences written by formulas (including the lowest-MQL-rate campaign at scale), net cash and spend by month with paid MQL rate on a second axis, ROAS as reported against net cash |
| Campaign scorecard | Every paid campaign for the window: spend, impressions, CTR, CPL, MQL rate, calls, cost per call, cash and ROAS, with data bars, colour scales and flags |
| Email health | By sending domain and by email type, with the 2% bounce and 0.1% complaint limits flagged, and a weekly bounce chart by domain |
| Revenue truth | The CRM-to-cash bridge with a waterfall chart and a $0 residual, and platform claims against warehouse cash |
| Funnel and test | Lead to renewal with stage conversion, and the CTA test with its decision written by a formula |
| Data quality | Checks against target, the short-link registry, the incident register, the renewal queue |
| Audit | 14 reconciliation checks over the data sheets, all zero |
| Definitions | The metric catalog |

Formulas read as words (`=SUMIFS(pd_spend_cents,pd_day,">="&WinStart,pd_day,"<="&WinEnd)/100`); the data sheets
are Excel tables; everything except the yellow input cells is locked, without a password. openpyxl builds
the file deterministically, and `--recalculate` opens it once in a private Excel instance so the committed
copy carries calculated values. `tests/test_bi.py` checks that the committed copy has the formulas of a
fresh build, and that the values Excel calculated equal the same figures computed in Python from the CSVs.
On the default window the workbook and the report agree to the cent: $309,900 net cash, $40.04 per paid
lead, a paid MQL rate of 19.8% against 20.9%, email bouncing at 3.40%, and meta_broad_v17 named as the
weakest campaign at scale.

## Production refresh

The embedded partitions suit a portfolio demo. For a live deployment, point each table's partition at the
warehouse (DuckDB over ODBC, a PostgreSQL schema, or the CSV share `export_bi` writes), publish to a
workspace, configure a gateway and schedule refresh after the nightly dbt build. Row-level security is not
defined because the report has one audience; add roles (for example by `dim_campaign[platform]` for a
paid-media team) before sharing it more widely. Label any additional page **Synthetic ScaleLab case**.
